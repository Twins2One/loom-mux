# 更新日志 · 0.8.13（2026-11-16）

> 接在 0.8.12 后面的一版小修，主要是「记忆抢救」的落点与收纳，另有几处发布链路的修正。

## 一、记忆抢救导出：跟着知识库走，只留最近 16 次

以前点「导出记忆数据」，会在**桌面**上新建一个 `Loom记忆抢救-<时间戳>` 文件夹，导出几次就堆几个，从不清理。

现在：

- 落点改成 **`<知识库根>/记忆抢救/Loom记忆抢救-<时间戳>`** —— 跟知识库数据放在一起管理，不再污染桌面。
- 每次导出后自动收尾，**只按时间顺序保留最近 16 次**，更早的整目录清掉。
- 导出结果里会回报「已清理旧导出」，清掉了哪几次看得见。
- 桌面落点只在开发/测试时用环境变量显式指定才会出现（`LOOM_EXPORT_DESKTOP`），正式使用不会再有。

## 二、设置面板与记忆库面板的文案收尾

- 删掉设置项里的重复解释（如复选框上方与标签重复的那句）。
- 「行动模式」→ **「AI思考强度」**，三档下方小字随选中项变化，只讲 agent 行为差异。
- 「上下文上限」→ **「单会话上下文上限」**，输入校验文案同步改口。
- 记忆库位置面板三行去掉多余括号：`形态：进程内 ONNX` / `来源：默认位置` / `目录存在：否`；长路径正常折行不撑破容器。

## 三、记忆库位置面板的两处死路

- **首启弹层「用新位置」**：新默认位置还不存在时，这个按钮原本点了必然失败。现在按后端回传的「新位置存在」把它禁用并说明——「先点『迁移』会连内容一起建过去」。
- **切到空目录的警告**：原本 600 毫秒就关层，等于没提醒。现在有关键提醒时不自动关，留「知道了」让作者读完。
- 顺带：弹层显示「迁移到：<目标路径>」；Esc 可关闭；失败后不再把「回退」按钮错点亮。

## 四、分块蒸馏的合并去重提速

`semantic_dedupe` 原本对**每个已有簇**都重算一次向量（O(n²) 次 ONNX 推理）。320 条条目实测要空转十几分钟。改成簇向量缓存后，同一测试 **53 秒 → 5.4 秒**，判定结果不变。

## 五、发布链路的修正

- 测试里那几处「打桩绕过、真连模型接口」的问题已修，跑测试不再发出外部请求。
- golden 快照改为与环境无关（不再随「这台机器有没有语义模型」变化），并去掉本机路径残留。
- CI 的 dev 依赖补上 numpy（两个 semantic 测试在导入阶段就需要它）。

## 升级说明

- 覆盖安装即可，不迁移数据；`%USERPROFILE%\.loom` 下的书稿、账户、配置都不动。
- 如果你之前导出过「记忆抢救」，那些**桌面上旧的文件夹不会被自动搬走**（新逻辑只影响以后的导出），可以手动挪进知识库下的 `记忆抢救` 目录，或直接删掉（里面只有速记本原文副本）。
